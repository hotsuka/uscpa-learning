# 教材PDFの一括取り込み

## このスキルが解こうとしている問題

2026-08-12 に BAR の教材を投入したとき、**47ファイルを渡して取り込まれたのが15ファイル**になり、
その理由が最後まで説明されないまま6往復した。差の内訳は後から分かれば当たり前のもので

- Discipline 3科目（BAR / ISC / TCP）が1つのダウンロードセットに混ざっていた
- 同じ単元にテキストと「回答あり」版があり、二重に数えていた
- 既に `reference/` にあるものが再度混ざっていた

**件数の差そのものは正常。異常なのは、差が出たことを取り込んだ後に気づく流れのほう。**
だからこのスキルは、**コピーする前に必ず内訳表を出して止まる**。

## 設計方針

判断（どのファイルがどの単元か）と機械的検査（命名・重複・件数）を分ける。
LLMがやるのはファイル名から単元を読み取るところだけで、
**命名規則の適用・重複判定・件数突合はスクリプトに固定する**。手で数えない。

| 層 | 手段 | 落とすもの |
| --- | --- | --- |
| 1 | `node .claude/skills/material-import/materials.mjs scan` | 両側のインベントリ、科目・種別の内訳、対象外の理由 |
| 2 | Claude が計画JSONを書く | 元ファイル名 → 正規化後のファイル名の対応づけ |
| 3 | `materials.mjs apply --plan <file>` | 命名規則違反・重複・科目外の検出、コピー、突合レポート |

## 命名規則（`reference/` の正）

```
{科目}_{単元名}_{種別}[_{番号}][_回答あり].pdf
```

| 要素 | 取りうる値 | 備考 |
| --- | --- | --- |
| 科目 | `FAR` `AUD` `REG` `BAR` `ISC` `TCP` | コア3＋Discipline3。`BEC` は旧制度の残置で新規追加しない |
| 単元名 | 英語の単元名そのまま | `&` や空白を含んでよい。アンダースコアは使わない |
| 種別 | `テキスト` `演習問題` | この2つ以外は作らない |
| 番号 | `M44` `CH51` 等 | 演習問題のみ。`M`＝モジュール、`CH`＝チャプターで**別体系**。同じ単元に両方あるのは正常で重複ではない |
| 回答あり | `_回答あり` | 解答付き版。無印版とは別ファイルとして両方持つ |

例:

```
BAR_Financial Management_テキスト.pdf
BAR_Financial Management_テキスト_回答あり.pdf
BAR_Financial Management_演習問題_M44.pdf
BAR_Financial Management_演習問題_CH51.pdf
```

**`M44` と `CH51` を同じものとして片方に寄せない。** 2026-08-15 に同じ問いが出ている。
モジュール別編成とチャプター別編成で収録範囲が違うため、両方を保持する。

## 手順

### Step 0. 対象科目を確定する（省略禁止）

取り込み先の科目を**先に1つ確定させる**。ダウンロードセットには受験しない科目が混ざるのが常態で、
ここを決めずに始めると Step 2 の対象外がすべて「取りこぼし」に見える。

引数に科目名があればそれを使う。無ければ聞く。**推測で始めない。**

### Step 1. 両側を棚卸しする

```bash
node .claude/skills/material-import/materials.mjs scan --src ~/Downloads --subject BAR
```

- `--src` 未指定時は `~/Downloads`
- 取り込み先の `reference/` と、ソース側のPDFを両方数えて内訳を出す
- ソース側のファイル名は正規化前なので、科目の判定は**ファイル名に科目コードが含まれるかどうかだけ**で行う。
  含まれないものは `未判定` に落ちる（Step 2 でClaudeが読む）

### Step 2. 内訳を提示して止まる（省略禁止）

`scan` の出力をそのまま貼るのではなく、**次の形に整理してユーザへ出す**。

```
渡されたPDF: 47本
  ├ 対象（BAR）        : 21本
  │   ├ 新規           : 15本  ← 実際に増えるのはこれ
  │   └ 既に reference/ にある: 6本
  └ 対象外             : 26本
      ├ ISC（今回受験しない Discipline）: 19本
      └ 科目コードが読めない            :  7本  ← 一覧を添える
```

**「実際に増えるのは15本」を先に言う。** これを言わずにコピーすると、
後から「47個渡して15個なのはなぜ」と聞かれ、そこから逆算して説明することになる。

対象外に落ちたものは**必ずファイル名を列挙する**。件数だけだと取りこぼしと区別がつかない。
ここでユーザの確認を待つ。**勝手にコピーへ進まない。**

### Step 3. 計画JSONを書く

`_work/import-plan.json` に、元ファイル名と正規化後のファイル名の対応を書く。

```json
{
  "subject": "BAR",
  "items": [
    {
      "src": "Proactive_BAR_M44_FinancialManagement.pdf",
      "dest": "BAR_Financial Management_演習問題_M44.pdf"
    },
    {
      "src": "skip_me.pdf",
      "skip": "ISC（今回対象外）"
    }
  ]
}
```

- `dest` は命名規則に厳密に従う。`skip` を書いたものはコピーしない（理由を必ず添える）
- **ソースの全ファイルを列挙する。** 書かれていないファイルがあると `apply` が落ちる。
  「書き忘れ」と「意図的な除外」を区別できないため

### Step 4. 検証してコピーする

```bash
node .claude/skills/material-import/materials.mjs apply --plan scripts/_work/import-plan.json --subject BAR
```

まず `--dry-run`（既定）で回り、次を弾く。

- 命名規則に合わない `dest`
- `reference/` に既にある `dest`（上書きしない）
- 計画内での `dest` 重複
- ソースに存在しない `src`、計画に無いソースファイル

すべて通ったら `--apply` を付けて実行する。**コピーであって移動ではない。**
ダウンロード元は残す（再取得の手間を避けるため）。

### Step 5. 突合レポートを出す

`apply` が最後に出す突合をそのまま報告する。Step 2 で予告した「新規15本」と
**実際にコピーされた本数が一致していること**を明示する。ずれていたら止めて原因を出す。

## 現状の例外（2026-08-15 時点。作成時に実データで確認した）

`reference/` は74本。うち**11本は規約が固まる前のFARファイルで、種別（テキスト／演習問題）が付いていない**。

```
FAR_Cash Flows.pdf / FAR_Cash Flows_回答あり.pdf / FAR_Consolidation.pdf /
FAR_Consolidation_回答あり.pdf / FAR_Credit Loss.pdf / FAR_Deffered Tax.pdf /
FAR_Leases.pdf / FAR_Leases_回答あり.pdf / FAR_Partnership.pdf /
FAR_Partnership_回答あり.pdf / FAR_Revenue Recognition & IS Presentation.pdf
```

`scan` はこれを毎回 `[要確認] 命名規則に合わない` として出す。**既知の残置であって不具合ではない。**
FARは受験済みなので急いで直す必要はないが、リネームするなら同名の `_テキスト` 版が別に存在するものが
あるので（例: `FAR_Deffered Tax.pdf` と `FAR_Deffered Tax_テキスト.pdf`）、中身を見てから決めること。

`reference/BAR_upload/` に BAR 20本と同じものが入っている。2026-08-12 のアプリ投入作業で作った
中間フォルダで、`reference/` 直下と重複している。`scan` はサブフォルダを見ないため集計には影響しない。

## 押さえどころ

- **件数の差は先に説明する。** このスキルの存在理由がここにある
- **回答あり版は別ファイル。** テキスト18種に対しファイル36本、というのは正常
- **`M` と `CH` は別体系。** 統合しない
- **BEC は旧制度。** `reference/` に4本あるが履歴であって、新規追加はしない
- **`reference/` はアプリの参照先ではない。** アプリ側の教材はブラウザのIndexedDBに入るので、
  ここへの格納とアプリへのアップロードは別作業。取り込み完了＝アプリで見える、ではない
- 問題データ（`src/data/questions/`）への投入は別スキル（`tbs-add`）と
  既存の `stage-*.mjs` / `merge-staged-*.mjs` が担当する。本スキルはPDFの格納までで止まる
